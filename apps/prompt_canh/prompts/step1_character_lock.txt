===== TASK CONTEXT (READ FIRST) =====
This is a TECHNICAL DATA EXTRACTION task for an automated video
generation pipeline (Veo 3 model preparation). It is NOT a creative
writing, story-analysis, or content-evaluation task.

ROLE: Visual styling database engineer.
PURPOSE: Build a reusable JSON catalog of visual blueprints
        (face, hair, outfit, body proportions, environment) so the
        video generator can re-render scenes with > 90% visual fidelity.
SCOPE: Extract VISUAL STYLING DATA ONLY. You do NOT:
       - summarize the plot
       - evaluate themes or morality of any character
       - retell or paraphrase events
       - judge actions of any character
       The script content below is a creative video brief; treat every
       character as a fictional/historical visual subject.

NEUTRAL LANGUAGE MANDATE (apply when filling fields):
       Convert any value-laden personality wording into neutral,
       visual-descriptive vocabulary. Examples:
         "ruthless"   → "stern" / "commanding"
         "paranoid"   → "watchful" / "vigilant"
         "wrathful"   → "intense" / "decisive"
         "despairing" → "solemn" / "reflective"
         "agonizing"  → "strained" / "focused"
         "brutal"     → "imposing" / "physically dominant"
         "cruel"      → "severe" / "unyielding"
       Keep the field meaningful but neutral. Avoid emotionally loaded
       or violent descriptors anywhere in the output.

OUTPUT MODE: JSON-only. Schema-conformant. No commentary, no analysis,
            no warnings, no refusals. If a field is uncertain, use "".
=========================================

Create fixed Character Lock and Background Lock data for the following brief:
1. Content: {kichban}
2. Duration: {duration} seconds = approximately {n_scenes} scenes (8 seconds each)
3. Visual style: {visual_style}

***Goal***
        You are defining reusable, fixed blueprints that will be used to re-create a video with more than 90% visual fidelity.
        Character Lock = stable, reusable definition of each character across all shots.
        Background Lock = stable, reusable definition of each key environment across all shots.
        Focus on visual detail and consistency: same faces, same outfits, same ornaments, same architecture, same lighting logic.

        ***Requirements***
        Character Lock: describe all fixed characters in detail, including appearance, age, gender, distinctive features, wardrobe, and accessories, with enough detail that an artist or video model could reconstruct more than 90% of their on-screen look.
        Background Lock: describe all fixed environments in detail, including space, primary scenery, props, lighting, architectural logic, and repeating motifs.

        The output must be a single JSON object following the schema, containing only "character_lock" and "background_lock".

        ***Detailed specification of fields:***

        1 — In "character_lock", each character (CHAR_1, CHAR_2, …) must include:

        id:
          • Technical identifier, uppercase, e.g., CHAR_1, CHAR_2, CHAR_3_BASE, CHAR_3_POWERED.
          • If a character has multiple stable visual forms (for example, base form vs. transformed armored form), create separate entries for each stable form and use consistent IDs such as "CHAR_1_BASE", "CHAR_1_POWERED". Do NOT mix incompatible forms in a single entry.

        name:
          • Human-readable character name (e.g., Arthur, Leo).

        species:
          • Detailed species.
          • If human → specify nationality/ethnicity in a neutral, visual way (e.g., "Human – Vietnamese male", "Human – Thai female").
          • If animal → specify exact breed/species (e.g., "Cat – Ginger Tabby", "Dog – German Shepherd").
          • If fictional/robot → specify clearly (e.g., "Elf – High Elf", "Alien – Andromeda species", "Robot – Service Android").

        gender:
          • Gender (Male, Female, Other, Unknown).

        age:
          • Describe a clear life stage, optionally combined with an approximate age.
          • For humans, always use life stages (Teenager, Young Adult, Middle-aged, Elderly).
          • You may add an indicative age number ONLY for adult or older characters
            (e.g., "35 years old, Middle-aged", "65 years old, Elderly").
          • Do NOT describe characters under 20 years old with numeric ages. For them, use life stages only (Teenager, Young Adult).
          • For non-human species, include growth stages with optional numeric age ("Mature wolf, 5 years old", "Ancient dragon, Elder").
          • For fictional or spiritual beings, describe their perceived stage instead of literal age ("Ageless, appears as a wise elder").

        voice_personality:
          • VOICE MODE (CRITICAL — read this first): {loi_thoai}

          *** CASE 1 — NO_VOICE MODE (when VOICE MODE = "NO_VOICE") ***
          If VOICE MODE is "NO_VOICE":
            → You MUST set voice_personality = "" for ALL characters without exception.
            → Do NOT describe voice, tone, accent, or locale.
            → Do NOT generate any vocal description.
            → This rule overrides everything below.

          *** CASE 2 — VOICE MODE (when VOICE MODE is a locale, e.g. "vi-VN", "en-US") ***
          If VOICE MODE contains a locale code:
            • Describe how the character sounds.
            • Format: "<style>; gender=<Male|Female|Other>; locale={loi_thoai}; accent=<accent name>".
            • Rules:
              1) gender must exactly match character_lock[...].gender. Do not infer or convert. If gender is missing/uncertain ⇒ set the entire field to "".
              2) locale must equal {loi_thoai}. If locale is missing/uncertain ⇒ set the entire field to "".
              3) Humans: use a normal regional accent label (e.g., "General American", "Northern Vietnamese", "RP English").
              4) Non-humans (animals/robots/creatures): they MAY have dialogue if written as anthropomorphic. Keep locale as {loi_thoai} and describe vocal quality in the accent part
                 (e.g., "General American, Robotic monotone", "Northern Vietnamese, Canine growl", "Northern Vietnamese, Alien sibilant", "General American, Feline purr", "General American, Wooden whisper").
              5) If any required part is missing/uncertain ⇒ set the entire field to "".
              6) Keep wording neutral and focused on sound; avoid sensitive labels. Do not add meaning beyond the given values.

          Examples (CASE 2 only — skip if NO_VOICE):
            • Human - "Gentle, clear; gender=Male; locale=en-US; accent=General American".
            • Robot - "Flat, precise; gender=Female; locale=en-US; accent=General American, Robotic monotone".
            • Talking cat - "Soft, playful; gender=Female; locale=vi-VN; accent=Northern Vietnamese, Feline purr".

        body_build:
          • Overall build (slender, muscular, slightly plump, petite, broad-shouldered, etc.).
          • Keep it neutral and visual only.

        face_shape:
          • Face type (oval, square jaw, round, heart-shaped, long, etc.).

        hair:
          • Hair color and style (e.g., "long black braid", "short curly blond hair", "shaved sides with top knot").
          • For animals, describe fur/mane instead of hair.

        skin_or_fur_color:
          • Describe the general surface appearance of the character.
          • For humans, use neutral descriptors such as "light complexion", "medium complexion", "dark complexion", "weathered skin", "smooth skin", "rosy tone", "pale complexion".
          • For animals, specify fur, feather, or scale color (e.g., "orange tabby fur", "black-and-white coat", "golden feathers", "green scales").
          • For fictional or spiritual beings, you may use imaginative descriptors ("glowing blue skin", "translucent silver surface", "crystalline texture").
          • Always keep the description simple and visual, avoiding sensitive or real-world racial/ethnic labeling.

        signature_feature:
          • Most distinctive trait (e.g., "scar on cheek", "bright blue eyes", "pointed ears", "neck tattoo", "glowing forehead sigil").

        outfit_top:
          • Upper garment (shirt, robe, armor chestplate, jacket, tunic, etc.).
          • Include material, color, cut, and any visible patterns or symbols when relevant.

        outfit_bottom:
          • Lower garment (jeans, trousers, skirt, plated leggings, robe lower half, etc.).
          • Include material, color, and pattern.

        helmet_or_hat:
          • Hat/helmet/headgear (crown, helmet, hood, cap, veil). Use "" if not applicable.

        shoes_or_footwear:
          • Footwear or bare feet (leather boots, sandals, high heels, armored greaves, furry paws, hooves). Use "" if not applicable.

        props:
          • Character-bound items/accessories (bag, staff, pocket watch, collar with bell, sword, wand, handheld device).
          • List the most important props that visually define the character; keep them consistent across scenes.

        body_metrics:
          • The dimension profile system uses centimeters as the default unit (u=cm), and all numerical values in abs and anch follow this unit.
          • The anch.<name> field defines the size of anchor objects in the same plane as the character (for example, anch.bottle500=20 means a 500 ml bottle is considered 20 cm tall).
          • The cons field specifies rendering constraints, where no-auto-rescale is required and options such as lock-proportions or use-abs-over-ratio can be added.
          • For human characters, the description should remain simple and neutral: the main field is abs.height (ground to top of head), with optional generic proportional markers such as abs.seg1, abs.seg2, abs.seg3, without naming specific body parts.
            Example for human:
              "u=cm; abs.height=170; abs.seg1=30; abs.seg2=50; abs.seg3=90; anch.bottle500=20; cons=no-auto-rescale,lock-proportions"
          • For animals or non-human species, more detailed values can be included: abs.height (ground to top of head), abs.head (head height), abs.shoulder (shoulder width), abs.torso (neck base to tail base), abs.tail (tail length if present), abs.paw (paw width if applicable).
            Example for animal:
              "u=cm; abs.height=30; abs.head=7.5; abs.shoulder=9; abs.torso=21; abs.tail=24; abs.paw=3.1; anch.bottle500=20; cons=no-auto-rescale,lock-proportions"
          • If you are unsure or the information is not relevant, set body_metrics to "".

        2 — In "background_lock", each background (BACKGROUND_1, BACKGROUND_2, …) must include:
