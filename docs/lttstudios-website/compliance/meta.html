Meta Platform Compliance

How we map every Meta Platform Term to specific bot behavior. Designed for fast reviewer verification.

Our compliance commitment

LTTStudios VideoBot is built to comply with all Meta Platform Terms, Developer Policies, and Community Standards. This page maps each policy area to specific bot behavior so Meta reviewers and auditors can verify compliance quickly.

OAuth scopes & their use

ScopeWhat the bot does with itWhere in code
pages_show_list Calls GET /me/accounts ONCE after OAuth to populate the Page picker. The list is cached locally and refreshed only on user action. core/auth_manager.py:274
pages_manage_posts Calls POST /{page_id}/videos (feed) and POST /{page_id}/video_reels (Reels) for user-supplied content only. Each call requires explicit user action (sheet row or manual button). core/graph_uploader.py, core/reels_uploader.py
pages_read_engagement Calls GET /{video_id}/video_insights for the Monitor dashboard. Only fetches data for videos the user published through the bot. core/insights_fetcher.py
pages_manage_engagement Optional first-comment via POST /{video_id}/comments. Comment text comes from user's sheet column. Reels excluded. core/facebook/commenter.py

Platform Terms alignment

Term: Use APIs only for permitted purposes

The bot only calls documented endpoints in graph.facebook.com for the user's own Pages. No scraping, no undocumented endpoints, no mobile API spoofing. Full endpoint list: Architecture page.

Term: Don't enable spam, abuse, or harassment

Multi-layer anti-spam built in:

  • Hard rate limits: 4h between same-Page posts, 3 posts/Page/day
  • SHA-256 + perceptual hash dedup (30-day window)
  • Page warm-up cap for Pages <30 days old
  • Circuit breaker on FB error codes 4, 17, 32, 368 (spam-related)
  • Caption Rotator disabled by default (no auto-CTA)
  • Active hours window (default 7am-10pm) — no late-night spam

Term: Respect rate limits

Bot honors documented FB rate limits with conservative client-side enforcement that's stricter than Meta's actual limits. Backoff on code=4 (rate limit), code=32 (rate limit), code=368 (spam-related cooldown).

Term: Use user data only as authorized

User authorizes specific scopes via OAuth. Bot never accesses:

  • Friends lists (no user_friends scope)
  • Private messages (no read_mailbox scope)
  • Other Pages the user doesn't admin
  • Any data outside what OAuth explicitly granted

Term: Provide privacy policy + data deletion

  • Privacy Policy: /legal/privacy.html — comprehensive disclosure of all FB data accessed and how it's used
  • Data Deletion: /legal/data-deletion.html — self-service + email request, 30-day completion per GDPR Art. 17
  • DPA: /legal/dpa.html — for enterprise customers

Term: Notify users of breaches

Our security policy commits to 72-hour breach notification per GDPR Article 33. See Security policy.
