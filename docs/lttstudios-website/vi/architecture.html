Kiến trúc & API Reference

Technical reference đầy đủ cho LTTStudios VideoBot — mọi API endpoint được gọi, OAuth scope được dùng, data flow path. Designed cho Meta và TikTok app reviewer + security auditor. Nội dung kỹ thuật giữ tiếng Anh để khớp Meta/TikTok documentation chính thức.

System overview

LTTStudios VideoBot is a standalone Windows desktop application. The bot itself, the user's content queue (Google Sheets), and the user's video library (Google Drive) all sit on the user's side. The bot calls vendor APIs directly from the user's machine — there is no LTTStudios backend.

OAuth flow (Facebook example)

1. User clicks "Connect Facebook" in bot
   ↓
2. Bot opens browser to:
   https://www.facebook.com/v21.0/dialog/oauth?
     client_id={app_id}&
     redirect_uri=https://lttstudios.com/auth/fb-callback.html&
     scope=pages_show_list,pages_manage_posts,
           pages_read_engagement,pages_manage_engagement&
     response_type=code&
     state={csrf_token}
   ↓
3. User approves on Facebook
   ↓
4. FB redirects to lttstudios.com/auth/fb-callback.html?code=...&state=...
   ↓
5. Callback page (JS) validates state, POSTs code to:
   http://127.0.0.1:8765/callback  (bot's local HTTPServer)
   ↓
6. Bot exchanges code for short-lived token via:
   POST graph.facebook.com/v21.0/oauth/access_token
   ↓
7. Bot exchanges short → long-lived (60 day):
   POST oauth/access_token?grant_type=fb_exchange_token
   ↓
8. Bot fetches user's Pages:
   GET /me/accounts?fields=id,name,access_token,category
   ↓
9. User picks Pages → saved encrypted to data/tokens.enc

Cross-machine OAuth (TikTok)

1. User clicks "Connect TikTok" — bot shows QR code dialog
   ↓
2. User scans QR with phone (logged into TikTok)
   ↓
3. TikTok redirects phone browser to:
   https://lttstudios.com/legal/callback.html?code=...
   ↓
4. Callback page POSTs to relay:
   POST lttstudios.com/api/oauth-relay/store.php
   Body: code, state, scopes
   Signed with HMAC-SHA256 (300s timestamp validity)
   ↓
5. Bot polls relay every 2s:
   GET lttstudios.com/api/oauth-relay/fetch.php?state=...&sig=...
   ↓
6. Bot receives code → exchanges for tokens (same as step 6+ above)

Anti-spam algorithms

AlgorithmImplementationPurpose
SHA-256 content dedup hashlib.sha256(video_bytes) Prevent re-posting identical bytes to same target within 30 days
Perceptual hash (pHash) Custom dHash variant, 64-bit, threshold 2 Hamming Catch re-encoded variants of same video
Cross-target warning Same video on ≥3 different Pages within 7 days Detect page-farm spam pattern
Page warm-up cap FB Page age <30 days → reduced daily cap Respect FB's stricter limits for new Pages
Circuit breaker Per platform:target_id, exponential backoff Pause publish to a failing target (15 min → 1h → 24h)
Session lock File-based lock in data/session_locks/ Prevent two bot instances publishing to same account
Random row order Shuffle pending rows per scan (configurable) Avoid posting in deterministic order (bot signature)
Caption rotator Deterministic per (target, video, day) — OFF by default Per-target caption variation (off by default to respect user content)

Rate limit enforcement

The bot's RateLimiter is the central authority for all publish operations. Defaults (configurable in Settings):

min_interval_per_page_s        = 14400  # 4 hours between posts on same Page
min_inter_page_interval_s      = 900    # 15 minutes between posts on different Pages
max_posts_per_page_per_day     = 3      # hard cap
max_posts_per_account_per_day  = 12     # cap across all Pages of one account
jitter_s                       = 600    # ±10 min random delay (anti-pattern)
active_hours_start             = 7      # 7am ICT
active_hours_end               = 22     # 10pm ICT
skip_overdue_minutes           = 60     # skip rows whose schedule is >60min overdue

Backoff applied for Meta error codes: 4 (rate limit), 17, 32, 368 (spam), 322. Cooldown values match Meta's documented backoff guidance.

Audit log format

Every publish, OAuth, comment, and admin action is appended to data/audit_log.jsonl as one JSON object per line:

{"ts":"2026-06-04T10:30:00Z","event":"video_published",
 "platform":"facebook","page_id":"123456","video_id":"789012",
 "duration_s":367,"row_idx":18}
{"ts":"2026-06-04T10:30:15Z","event":"comment_posted",
 "platform":"facebook","video_id":"789012","comment_id":"345678"}
{"ts":"2026-06-04T11:15:00Z","event":"token_refresh",
 "platform":"facebook","account_id":"abc","new_expiry":"2026-08-03T11:15:00Z"}

No caption content, no email addresses, no token values in audit log. Rotation: 10MB cap, 5 backup files retained.

Where this matters

For Meta App reviewers

This page documents every Graph API endpoint we call. Cross-reference with our Privacy Policy Section 3.1 (which lists OAuth scopes) and Products page (which describes user-facing features). The OAuth scope mapping above shows exactly which permission unlocks which feature — there is no "extra" permission requested beyond what's actively used.

For TikTok auditors

Every TikTok endpoint used is listed above with the required scope. The bot enforces privacy_level=SELF_ONLY in Sandbox mode via the ComplianceGuard module (core/tiktok/compliance_guard.py). User consent is recorded in tiktok_confirmed_at sheet column per the Direct Post audit requirement.
