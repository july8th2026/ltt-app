Câu hỏi thường gặp

Câu hỏi setup phổ biến, OAuth issues, rate limit, troubleshooting cho Facebook Graph API v21 + TikTok Content Posting API v2. Nếu câu của bạn chưa có ở đây, email support@lttstudios.com.

Bắt đầu

Cài bot trên Windows thế nào?

1. Tải .zip mới nhất tại trang download.
2. Giải nén bất kỳ đâu (Desktop, Documents...).
3. Chạy setup_new_machine.bat 1 lần — script check Python 3.10+, tạo virtual environment, cài dependencies (customtkinter, google-api-python-client, cryptography, requests, qrcode), validate config.
4. Chạy run_gui.bat để mở app.

Script setup là idempotent — chạy lại an toàn nếu có lỗi.

Cần credentials gì để dùng?

Bạn tự chuẩn bị:

  • Meta Developer App (miễn phí) — cho Facebook Page publishing. Cần scope pages_show_list, pages_manage_posts, pages_read_engagement, pages_manage_engagement
  • TikTok Developer App (miễn phí) — cho TikTok publishing. Cần scope user.info.basic, video.upload, video.publish
  • Google Cloud OAuth credentials (free tier đủ) — cho Sheets API v4 + Drive API v3 access

Bot KHÔNG cung cấp credentials. Bạn nhập trong Settings tab lần đầu. Chúng tôi không bao giờ thấy credentials của bạn vì không có server LTTStudios.

Kết nối Page Facebook thế nào?

Mở bot → click tab FB Accounts → click Connect Facebook Account. Browser mở FB OAuth dialog. Login, grant permission, được redirect về callback page tại lttstudios.com/auth/fb-callback.html.

Bot tự động gọi GET /me/accounts để lấy list Page bạn admin. Tick Page muốn enable publish, click Save. Token lưu mã hoá AES-128 Fernet cho từng Page riêng biệt.

Kết nối tài khoản TikTok thế nào?

Tab TikTok Accounts → Connect TikTok Account. Có 2 cách:

  • Cùng máy: browser mở TikTok OAuth → login → grant scope
  • Khác máy (QR code): bot hiện QR code → scan bằng phone đã login TikTok → complete OAuth trên phone. Callback POST về relay endpoint lttstudios.com/api/oauth-relay/store.php với HMAC-SHA256 signed, bot poll relay để pull code.

Permissions & visibility

Vì sao video hiển thị "công khai" nhưng không ai xem được?

Câu hỏi #1 của user mới. Nguyên nhân hầu như luôn là: Meta App của bạn đang Development Mode và chưa pass App Review.

Facebook ẩn bài tạo qua app chưa review, dù bài hiện "Published" và "Public" trong Business Suite. Đây là chính sách Meta từ Q3/2021. Fix: submit Meta App Review cho permission pages_manage_posts + pages_manage_engagement. Xem about page để biết chúng tôi đang work qua quy trình này như thế nào.

Bài bị "Hạn chế hiển thị" (Reduced distribution). Vì sao?

Facebook spam filter giảm reach organic cho bài đó. Trigger phổ biến:

  • Quá nhiều hashtag (FB khuyến nghị ≤ 5)
  • External link kiểu sub-promotion ("youtube.com/...?sub_confirmation=1")
  • "Engagement bait" ("Comment phía dưới!" "Tag bạn bè!")
  • Page mới score trust thấp
  • Content trigger nudity/violence/misinformation classifier (kể cả false positive)

Fix: review caption, bỏ trigger, viết tự nhiên hơn. Bot không tự thêm hashtag/CTA trừ khi bật Caption Rotator (mặc định OFF).

TikTok Direct Post đang Sandbox — đăng được không?

Trong Sandbox mode, TikTok bắt buộc privacy_level = SELF_ONLY cho mọi post. Bot tự enforce điều này qua ComplianceGuard. Bài đăng được nhưng chỉ creator xem được, public không thấy.

Để direct public post cần submit TikTok app audit và được approve. Xem trang Audit trong bot để check readiness.

Rate limit & scheduling

Bot có thể đăng bao nhiêu lên 1 Page mỗi ngày?

Default bảo thủ:

  • min_interval_per_page_s = 14400 — 4 giờ giữa các post cùng Page
  • min_inter_page_interval_s = 900 — 15 phút giữa các Page khác
  • max_posts_per_page_per_day = 3 — hard cap/Page/ngày
  • max_posts_per_account_per_day = 12 — cap toàn tài khoản
  • jitter_s = 600 — random delay ±10 phút (chống pattern bot)
  • active_hours_start = 7, active_hours_end = 22 — chỉ chạy 7h-22h

Tuned để stay trong threshold spam của Facebook. Có thể adjust trong Settings nhưng tăng risk Page warning. Page mới (<30 ngày) còn có warmup cap thấp hơn tự động áp dụng.

Format thời gian schedule_time?

Bot accept 8 format:

2026-06-15 14:30        ← khuyên dùng
2026-06-15 14:30:00
15/06/2026 14:30
15-06-2026 14:30
2026-06-15T14:30
2026-06-15T14:30:00
... và serial date float từ Google Sheets

Timezone theo config timezone (default Asia/Ho_Chi_Minh = UTC+7).

Để publish ngay, điền giờ gì?

Điền giờ hiện tại hoặc lùi tối đa 60 phút. Bot pickup row có schedule_time ≤ now và không quá skip_overdue_minutes (default 60 phút). Row có schedule_time trống KHÔNG được pickup (đã thay đổi từ v1.0.0).

Tip: dùng =NOW() trong Google Sheet, copy as value.

Lỗi thường gặp

Lỗi: "(#100) Length of param title must be less than or equal to 255"

Facebook Graph API v21 cap title video tại 255 ký tự. Rút ngắn title trong cột tieu_de_seo của sheet.

Nếu bật Caption Rotator, nó wrap title với text khác → vượt limit. Tắt Rotator hoặc dùng base title ngắn hơn (Rotator mặc định OFF từ v1.0.0).

Lỗi: "Token Page hết hạn" / Code 190

Token Facebook Page hết hạn (long-lived ~60 ngày). Re-OAuth account:

Settings → FB Accounts → click Reconnect bên Page bị lỗi. Token mới sẽ replace cái cũ. Past posts và audit log không ảnh hưởng. Bot có background TokenRefresher chạy mỗi 1 giờ để auto-extend token 7 ngày trước khi expire — nhưng nếu lỡ rồi vẫn phải re-OAuth.

Anti-spam báo "video tương đồng" (pHash match) — false positive?

Thuật toán perceptual hash bản cũ (<v1.0.0) có bug false-positive (only 15-bit effective). Bản v1.0.0 đã:

  • Tighten match threshold từ 8 → 2 (giảm 175× false positive)
  • Reject degenerate hash values (0000... và ffff...)

Nếu vẫn false-positive, tạm tắt dedup bằng anti_spam_dedup = false (note: tắt cả SHA-256 dedup — bật lại sau khi upload).

Video upload thành Reel dù set post_type=feed. Vì sao?

Facebook tự classify video dọc (9:16) ≤ 90 giây thành Reel kể cả khi upload qua endpoint feed video (POST /{page_id}/videos). Log sẽ thấy facebook.com/reel/... thay vì facebook.com/videos/....

Để force feed (non-Reel): encode video 16:9 (vd 1920×1080) HOẶC duration > 90s. Phải đạt CẢ 2 điều kiện FB mới giữ là feed video.

Circuit breaker OPEN — bot dừng publish lên Page

Bot có circuit breaker per-account (key = platform:target_id). Sau N fail liên tục, breaker OPEN, dừng publish lên Page đó với cooldown theo FB documented backoff (15 phút → 1 giờ → 24 giờ tăng dần).

Verify Page health: vào FB Page Settings → Support Inbox → check có warning gì không. Đợi cooldown hoặc reset breaker (delete file data/circuit_breaker.db rồi restart bot — KHÔNG khuyên trừ khi chắc Page OK).

OAuth callback & cross-machine

Sau OAuth bot báo "Bot không phản hồi"

Trang callback (lttstudios.com/auth/fb-callback.html) POST OAuth code về HTTPServer local của bot tại 127.0.0.1:8765. Check:

  • Bot vẫn đang chạy khi complete OAuth
  • Windows Firewall không block port 8765 cho Python process
  • Antivirus không quarantine .exe
  • Thử re-initiate OAuth từ bot (Settings → Reconnect)

Bot listen trên 127.0.0.1 only (loopback) → không bị WAN attack.

OAuth TikTok trên máy khác (vd điện thoại) được không?

Có — bot support cross-machine TikTok OAuth qua QR code. Click Connect TikTok → dialog hiện QR code chứa OAuth URL. Scan bằng phone đã login TikTok, complete OAuth.

Callback POST về relay endpoint lttstudios.com/api/oauth-relay/store.php với HMAC-SHA256 signed payload (300s timestamp validity chống replay). Bot poll fetch.php để pull code.

Cần upload PHP relay file lên hosting. Nếu KHÔNG config, fallback same-machine OAuth (mở browser trên máy bot).

Sheets & Drive

Bot không thấy sheet — "Permission denied"

Một trong hai:

  1. Service Account: share Sheet với email service account (trong service_account.json tại key client_email) với quyền Editor.
  2. OAuth2: flow mở browser lần đầu — login với Google account sở hữu/có access Sheet. Token cache tại {credentials_path}.token.json.

Bot dùng Google Sheets API v4 + Drive API v3 chính thức, scope tối thiểu (chỉ Sheets read/write + Drive read).

Download Drive fail "virus scan warning"

Video > 100MB Google hiện trang confirm trước khi download. Bot xử lý tự động — parse form HTML, extract token, submit confirm. Nếu vẫn fail:

  • Verify link Drive có "Anyone with link can view"
  • Check bot có Drive read scope trong OAuth
  • Thử mở file trong incognito browser xác nhận accessible không login
  • Kiểm tra log logs/app.log có dòng "Drive download failed: ..."
Sheet header column phải đặt tên gì?

Default header names (configurable trong Settings):

video_drive_url    ← link Drive video gốc
schedule_time      ← giờ lên lịch (bắt buộc từ v1.0.0)
title              ← tiêu đề video
description        ← mô tả
keywords           ← keyword
thumbnail_url      ← link thumbnail (optional)
target_page        ← tên Page đăng (nếu sheet có nhiều Page)
post_type          ← "feed" hoặc "reels"
platform           ← "facebook" hoặc "tiktok"
comment            ← first comment (optional)
status             ← bot ghi: PENDING/RUNNING/DONE/ERROR/SKIPPED
video_url_fb       ← bot ghi link bài đã đăng
uploaded_at        ← bot ghi timestamp upload
error_message      ← bot ghi nếu fail

Data & privacy

Data lưu ở đâu?

Chỉ trên máy bạn. Token tại data/tokens.enc và data/tiktok_tokens.enc (mã hoá AES-128 Fernet, key từ Windows Machine GUID qua PBKDF2-HMAC-SHA256 200,000 iterations). Log tại logs/app.log. Audit trail tại data/audit_log.jsonl (JSONL append-only, rotation 10MB, max 5 backup). Cache video tại temp_videos/ (auto xoá sau upload mặc định).

Token mã hoá gắn máy → KHÔNG decrypt được nếu copy sang máy khác.

Không gì gửi về server LTTStudios — chúng tôi không có server.

Xoá toàn bộ data thế nào?

Xem chi tiết Trang Xoá Dữ liệu. Tóm tắt:

  1. Đóng bot
  2. Xoá folder cài bot
  3. Revoke app tại Facebook Settings → Business Integrations → tìm "Lttstudios" → Remove
  4. Cho TikTok: app TikTok → Settings & privacy → Security & permissions → Manage app permissions → Remove

Toàn bộ token, log, cache video sẽ bị xoá. GDPR Article 17 compliance.

Bot có gửi telemetry không?

KHÔNG. Bot không có analytics, không có crash reporting service, không phone-home. Chỉ liên hệ với Meta Graph API (graph.facebook.com), TikTok API (open.tiktokapis.com), Google APIs (googleapis.com), và Telegram API (api.telegram.org) khi user explicitly setup.

Có thể verify bằng cách monitor network traffic với Wireshark hoặc Fiddler.
