  người dùng (OAuth token, API key khách) vì nó không biết gì về "loại" secret.
- **KHÔNG có bảng credential theo người dùng** trong `models.py`

  (provider pool), không có `user_id` sở hữu theo nghĩa "khách tự thêm khoá của
  họ".

  `apps/` — grep `oauth|refresh_token` toàn `apps/`, `platform_core/`,

  link-local/multicast/reserved/unspecified + dải metadata cloud
  (`169.254.169.254`, `fd00:ec2::254` — SSRF cloud metadata kinh điển). Gọi lại
  SAU MỖI REDIRECT (chống DNS rebinding — TOCTOU).
- `server/api/context.py:58-66` có kiểm `ipaddress` riêng (khác mục đích — vẻ
  như IP allowlist cho trust proxy, không phải SSRF).
- `platform_core/public_api/anomalies.py` mô tả là khu vực chống SSRF/đọc chéo
  tài khoản/giả mạo (chưa đọc sâu nội dung).
- Hàm `validate_target()` **tái dùng được trực tiếp** cho một node "HTTP
  Request" của Workflow V2 — đã đúng bài toán (URL do khách nhập), chỉ cần gọi
  lại, không viết mới. Rủi ro: nó nằm trong `public_api/webhooks.py`, gắn với
  concept "webhook" — nên tách ra module dùng chung (`platform_core/`) nếu
  workflow node cũng cần, tránh workflow phải "import xuyên" module webhook.

- `quotes.py`: định giá trước khi submit (`/quotes` dùng chung
